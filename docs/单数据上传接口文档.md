# Runzo 单数据上传接口文档

## 1. 接口说明

- 接口名称：单数据上传
- 接口作用：前端传入一条训练数据参数，后端完成一次 `simulate -> watch-settle` 的完整调用
- 当前实现状态：已实现，可直接联调

## 2. 接口信息

- 方法：`POST`
- 路径：`/api/runzo/single-upload/execute`
- 请求体类型：`application/x-www-form-urlencoded` 或 `multipart/form-data`
- 返回类型：
  - 普通前后端联调：返回 `JSON`
  - 当前网页 HTMX 调用：返回 `HTML` 片段

前端如果是原生页面或 App，对接时**不要传** `HX-Request: true`，直接走 JSON 返回即可。

## 3. 请求头

### 3.1 当前建议传递

| 字段名 | 必填 | 说明 |
| --- | --- | --- |
| `ts-app-version` | 推荐 | App 版本号，例如 `2.6.0` |
| `x-ts-app-version` | 备选 | 与 `ts-app-version` 二选一即可 |

### 3.2 补充说明

- `ts-app-version` 支持两种传法：
  1. 请求头 `ts-app-version`
  2. 表单字段 `tsAppVersion`
- 当前优先级：
  - 请求头优先
  - 表单字段次之
- 如果两边都不传，会校验失败

## 4. 请求参数

## 4.1 公共字段

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `environment` | string | 否 | 运行环境，默认 `test`，可选：`test` / `preprod` |
| `userId` | string | 是 | 用户 ID |
| `authorization` | string | 是 | Bearer Token |
| `tsAppVersion` | string | 条件必填 | 当请求头未传 `ts-app-version` / `x-ts-app-version` 时必填 |
| `dailyId` | string | 是 | 训练计划 ID |
| `trainingType` | string | 是 | 训练类型 |
| `runningDistance` | number | 是 | 跑量距离，必须大于 0 |
| `stateDescription` | string | 否 | 自然语言描述调整训练数据强度 |
| `weekIndex` | integer | 否 | 周序号，必须大于 0 |
| `dayStartTime` | integer | 否 | 起始时间戳，必须大于 0 |
| `gender` | string | 否 | 默认 `male` |
| `age` | integer | 否 | 默认 `22`，必须大于 0 |
| `weight` | number | 否 | 默认 `75`，必须大于 0 |
| `height` | number | 否 | 默认 `175`，必须大于 0 |
| `hrMax` | integer | 否 | 默认 `198`，必须大于 0 |
| `hrRest` | integer | 否 | 默认 `65`，必须大于 0 |
| `targetDistance` | number | 否 | 默认 `5`，必须大于 0 |
| `intensityPreference` | string | 否 | 默认 `medium` |

## 4.2 `trainingType` 枚举值

| 值 | 说明 |
| --- | --- |
| `Easy` | 轻松跑 |
| `LSD` | 长距离慢跑 |
| `Rest` | 休息训练 |
| `ExtraSession` | 额外训练 |
| `Threshold` | 阈值训练 |
| `Interval` | 间歇训练 |

## 4.3 不同训练类型对应字段

### 4.3.1 `Easy` / `LSD` / `Rest` / `ExtraSession`

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `easyMinPace` | string | 是 | 主训练最小配速 |
| `easyMaxPace` | string | 是 | 主训练最大配速 |

### 4.3.2 `Threshold`

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `thresholdWarmupMinPace` | string | 是 | 热身最小配速 |
| `thresholdWarmupMaxPace` | string | 是 | 热身最大配速 |
| `thresholdWarmupDistance` | number | 否 | 热身距离 |
| `thresholdMainMinPace` | string | 是 | 主段最小配速 |
| `thresholdMainMaxPace` | string | 是 | 主段最大配速 |
| `thresholdMainDistance` | number | 否 | 主段距离 |

### 4.3.3 `Interval`

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `intervalBlock1MinPace` | string | 是 | 热身段最小配速 |
| `intervalBlock1MaxPace` | string | 是 | 热身段最大配速 |
| `intervalBlock1Distance` | number | 是 | 热身段距离 |
| `intervalBlock2MinPace` | string | 是 | 主训练段最小配速 |
| `intervalBlock2MaxPace` | string | 是 | 主训练段最大配速 |
| `intervalBlock2Distance` | number | 是 | 主训练段距离 |
| `intervalRepeatNum` | integer | 否 | 循环次数，默认 `1` |
| `intervalBlock3MinPace` | string | 是 | 慢跑段最小配速 |
| `intervalBlock3MaxPace` | string | 是 | 慢跑段最大配速 |
| `intervalBlock3Distance` | number | 是 | 慢跑段距离 |

## 6. 成功返回

当前接口成功时返回 HTTP `200`，返回体结构如下：

```json
{
  "success": true,
  "environment": "test",
  "execution_status": "执行成功",
  "summary": "单数据上传执行成功。",
  "error_message": null,
  "simulate_request": "{...JSON字符串...}",
  "simulate_response": "{...JSON字符串...}",
  "settlement_request": "{...JSON字符串...}",
  "settlement_response": "{...JSON字符串...}"
}
```

## 6.1 返回字段说明

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `success` | boolean | 是否执行成功 |
| `environment` | string | 当前运行环境，`test` 或 `preprod` |
| `execution_status` | string | 当前执行状态 |
| `summary` | string | 执行摘要 |
| `error_message` | string \| null | 错误信息 |
| `simulate_request` | string | simulate 请求体，JSON 字符串 |
| `simulate_response` | string | simulate 响应体，JSON 字符串 |
| `settlement_request` | string | watch-settle 请求体，JSON 字符串 |
| `settlement_response` | string | watch-settle 响应体，JSON 字符串 |

## 6.2 `execution_status` 可能值

| 值 | 说明 |
| --- | --- |
| `待开始` | 默认初始状态 |
| `执行中` | 服务端执行中 |
| `执行成功` | 调用成功 |
| `执行失败` | 调用失败 |

## 7. 失败返回

当前接口失败时返回 HTTP `400`，返回体结构如下：

```json
{
  "success": false,
  "environment": "test",
  "execution_status": "执行失败",
  "summary": "单数据上传执行失败。",
  "error_message": "主训练最小配速不能为空",
  "simulate_request": "",
  "simulate_response": "",
  "settlement_request": "",
  "settlement_response": ""
}
```

## 7.1 常见失败原因

- `userId` 为空
- `authorization` 为空
- `ts-app-version` 和 `tsAppVersion` 都没传
- `dailyId` 为空
- `trainingType` 不合法
- `runningDistance <= 0`
- 对应训练类型的必填字段缺失
- `simulate` 接口失败
- `watch-settle` 接口失败

## 8. 前端对接建议

- 前端当前只需要对接这一个接口即可
- 建议始终用普通 JSON 模式，不要传 `HX-Request: true`
- 建议固定通过请求头传 `ts-app-version`
- 页面上只需要展示：
  - `execution_status`
  - `summary`
  - `error_message`
- 如果是调试场景，可以展示：
  - `simulate_request`
  - `simulate_response`
  - `settlement_request`
  - `settlement_response`

## 9. 当前实现上的注意点

- 这个接口当前是表单取参，不是 JSON body
- `Authorization` 仍然是表单字段，不是请求头
- `userId` 仍然是表单字段，不是请求头
- `ts-app-version` 可以走请求头，也可以走表单字段

如果后续你要把它彻底收敛成前后端纯接口协议，下一步建议再改成：

- 统一 JSON body
- `Authorization` / `ts-app-version` 固定走请求头
- 返回体改成统一包裹结构
