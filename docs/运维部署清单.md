# Runzo 项目运维部署清单

## 项目说明

- 项目类型：`FastAPI + Jinja2 + HTMX` 的 Python Web 服务
- 运行入口：`app.main:app`
- Python 版本建议：`3.10+`
- 默认监听端口建议：`8000`
- 对外访问方式建议：`nginx -> uvicorn`

## 部署前必须确认

### 1. 部署形态

- 建议单实例部署
- 不建议多副本部署
- 不建议多 worker 部署

原因：

- 多数据上传任务使用服务端内存和后台线程维护任务状态
- 浏览器会话通过 Cookie 绑定到当前进程内存
- 如果部署成多实例或多 worker，请求可能落到不同进程，导致任务状态、继续执行、终止操作错乱

### 2. 服务器网络连通性

服务器必须能访问以下外部依赖：

- 测试环境 Mongo
- 预发布环境 Mongo
- `simulate` 接口
- 测试环境 `watch-settle`
- 预发布环境 `watch-settle`

如果服务器出网或白名单有限制，需要运维先确认这些地址和端口可达。

### 3. 安全要求

- 页面会输入 `Authorization`
- 建议至少部署在内网
- 如果对外访问，建议使用 `HTTPS`
- 建议由运维加访问控制，例如内网白名单或网关鉴权

## 环境变量

建议运维显式配置以下环境变量，不依赖代码内默认值。

### 基础配置

- `RUNZO_SIMULATE_URL`
- `RUNZO_DAY_SLEEP_SECONDS`
- `RUNZO_DEFAULT_LANG`
- `RUNZO_DEFAULT_TIME_ZONE`
- `RUNZO_DEFAULT_COUNTRY`

### 测试环境配置

- `RUNZO_TEST_MONGO_URI`
- `RUNZO_TEST_MONGO_DB`
- `RUNZO_TEST_MONGO_COLLECTION`
- `RUNZO_TEST_SETTLE_URL`

### 预发布环境配置

- `RUNZO_PREPROD_MONGO_URI`
- `RUNZO_PREPROD_MONGO_DB`
- `RUNZO_PREPROD_MONGO_COLLECTION`
- `RUNZO_PREPROD_SETTLE_URL`

## 启动方式

### 推荐命令

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

### 反向代理建议

- `nginx` 监听 `80/443`
- 转发到 `127.0.0.1:8000`

### systemd 建议

- 使用 `systemd` 托管
- 设置 `Restart=always`
- 使用固定虚拟环境路径

## 代码发布流程

### 首次部署

1. 运维拉取指定仓库和指定版本
2. 创建 Python 虚拟环境
3. 安装 `requirements.txt`
4. 配置环境变量
5. 启动 `uvicorn`
6. 配置 `nginx`
7. 提供固定访问地址给业务方

### 后续更新

建议按版本或 commit id 发布，不要直接让运维拉不确定的最新代码。

推荐流程：

1. 开发提交代码并完成自测
2. 开发提供版本号或 commit id
3. 运维拉取指定版本
4. 如有依赖变更，重新执行 `pip install -r requirements.txt`
5. 重启服务
6. 开发回归验证

## 当前代码中会影响部署的点

### 1. 任务状态是内存态

影响：

- 服务重启后，正在执行的多数据上传任务会丢失
- 不适合多实例负载均衡

对应代码：

- `app/services/task_manager_service.py`

### 2. 当前没有全局并发上限

影响：

- 不同浏览器会话可以各自创建任务
- 每个任务会占用一个后台线程
- 如果内部人员同时大量使用，服务器资源压力会升高

对应代码：

- `app/services/task_manager_service.py`

### 3. 环境连接信息存在默认值

影响：

- 如果运维没有显式配置环境变量，服务会直接使用代码里的默认 Mongo 和接口地址
- 这对正式部署不够可控

对应代码：

- `app/services/settings.py`

建议：

- 正式部署时必须通过环境变量覆盖

### 4. `ts-app-version` 现在由前端或调用方传入

影响：

- 前端如果不传，接口参数校验会失败

对应代码：

- `app/services/validation_service.py`
- `app/routes/api_routes.py`

### 5. Cookie 会话绑定当前进程

影响：

- 同一浏览器的任务状态依赖当前服务进程内存
- 更不适合多实例部署

对应代码：

- `app/services/session_service.py`
- `app/services/task_manager_service.py`

## 建议运维使用的最小部署方案

- 1 台 Linux 服务器
- 1 个 Python 虚拟环境
- 1 个 `uvicorn` 进程
- 1 个 `nginx`
- 通过 `systemd` 托管
